# Contributing to Journey

Journey is at the concept and planning stage. Contributions should help validate the product or build a small, reliable MVP.

## Before contributing
1. Read the README and documents in `docs/`.
2. Check open issues before starting work.
3. For a significant feature, open an issue describing the user problem and proposed solution.

## Development principles
- Keep the MVP focused on discovery, trust, and provider enquiries.
- Do not mark planned features as implemented.
- Validate all user input on the server.
- Protect user data and provider contact details.
- Label sponsored content transparently.
- Include tests for important business rules.

## Proposed workflow
1. Create a focused branch.
2. Make a small, reviewable change.
3. Run linting and tests.
4. Update documentation when behaviour or architecture changes.
5. Open a pull request with context, screenshots where relevant, and test results.
